## 1. 背景（2026-10-12 核对规则与代码）

用户把一篇文档导入为核心算法对象后发现：L4 归纳得正确，L1 却很潦草，也做了大量归纳；图片没有引用；L4 没有引用任何 L1；工作台点不开引用。核对后的原因：

1. **规则从没要求 L1 保留原文细节**。导入步骤（burrowl-work "导入已有资料"第 3 步）只写"方法、定义、计算写 L1"；RECORDING §4 的 L1 写法以实验报告为模板（问题 → 方法 → 结果 → 限制），AI 自然会把原文重新归纳一遍。
2. **没有完整展开**：文稿只有 `research_process` 和 `research_report`，没有"按原文顺序看完整内容"的视图。
3. **图片实际放不进来**：`memory.figure` 只显示数据目录内的受控附件（`services/memory/documents.py:471`），但没有任何工具能把图片放进数据目录，规则又禁止 AI 直接改数据目录；Skill 里也没提过图片。
4. **原文里的实验写不成实验类 L1**：`unit_type=experiment` 必须绑定 Run（`core/technical.py:126`），外部资料没有 Run；而 `unit_type` 只有 experiment / method / derivation / analysis，随笔、说明、观点类内容没有合适的位置。
5. **原件变了无从比较**：来源只存路径和指纹，旧版内容没有保存。
6. **L4 的 `technical_refs` 等允许为空**，规则也没要求在概括处引用下层。
7. **工作台**：来源和正文链接只显示纯文本 ID（`Memory.tsx:452-475`），正文中的 `[[…]]` 显示为原样文字。
8. **正文里的长 ID 没有检查**：RECORDING §6 要求正文用 `[[@短名]]`，但程序不检查，AI 照样可能写进 `MEM-<uuid>`、`SRC-<uuid>` 或 64 位哈希。
9. **工作台占用一个命令行窗口**；每次启动的端口和网址 token 都是随机的，上次的网址打不开；进程在任务管理器里只显示为 python.exe。

已有可复用的部分：`index/extract.py` 已能把登记的原件抽成带位置的分段文本（PDF 按页、pptx 按幻灯片、xlsx/csv 按行段、Markdown 按标题路径，图片有 OCR），抽出的图片放在可重建的缓存里，分段作为 source 投影进入检索。**缺 docx**。`burrowl backup` 默认连同数据目录外已登记的原件一起打包，`restore --map` 会重定向。

## 2. L0–L4 的本质原则（写进 RECORDING §1，规范性内容）

文档和工作的形态无法穷举：一篇材料可能一会儿是论文，一会儿是随笔，一会儿是实验说明；AI 交互中产生的内容也一样。因此**不按文档类型套模板，而是按内容片段判断它回答哪个问题**。类型表只作为示例。

**原则 1：每层回答一个问题。** 判断单位是一段内容，不是整篇文档。各层的压缩程度从 L1 到 L4 逐层增加：L1 不压缩，L3 只压缩到"仍能直接使用"，L4 只留入口所需的要点。

| 层 | 回答的问题 | 一句话 |
|---|---|---|
| L0 | 依据是什么、在哪里 | 原件登记，只读 |
| L1 | 具体是怎样的？ | 能复核的细节，完整保留 |
| L2 | 是怎么走到这里的？ | 实际发生或原文记载的过程 |
| L3 | 以后遇到类似问题该怎么用？ | 一切可能复用的经验，逐条带条件和反例 |
| L4 | 这是什么，现在到了哪一步，能用来做什么，接下来做什么？ | 对象的入口与当前状态 |

各层展开说明：

**L0 依据**
- 包含：原件（文档、数据、代码、日志）的登记说明：是什么、谁或哪次执行产生、针对什么问题、版本、怎么解释（列、单位、坐标）、有哪些限制；导入时的原文快照、有意省略的段落及理由。
- 不包含：对原件内容的转述（那是 L1）。没有读过的原件不能声称已核验全文。

**L1 细节：具体是怎样的**
- 包含：任何读者要复核、复算、复现或照着做时需要的内容：定义、公式与推导步骤、算法步骤与接口、参数与取值理由、实验设置与工况、结果表、图与图注、代码与命令、例子、原文的论证与观点原话、限制条件。
- 导入资料：保留原文中所有有用的内容，接近原文表述，按原文顺序；AI 的解释单独成块标"整理者注"。
- AI 研究交互：本次实际做了什么、怎么做、得到什么，写到别人能复算的程度；对话结束后这里是唯一完整的记录。
- 不包含：对多条细节的归纳评价（写 L3 / L4）；没有发生的过程（不编 L2）。

**L2 经过：是怎么走到这里的**
- 包含：起点与背景；按实际顺序的尝试、选择及理由、观察到的现象与失败、认识如何改变；当时还没解决的问题。写明来源是原文记载、本次工作，还是事后补写。
- 导入资料：只在原文写了形成过程（版本演进、排错经过、讨论纪要）时才写。
- AI 研究交互：有实际的探索、取舍或失败时写；只做了一步就如实写一步。
- 不包含：结果本身的细节（引用 L1）、编造的多轮演进。

**L3 经验：以后遇到类似问题该怎么用**
- 包含：**只要以后可能用得上的经验都留下，一条经验一条记录或一个结论**，不因为"太小""只遇到一次"而丢掉。每条写清：在什么问题和条件下、观察或结论是什么、怎么用、为什么有依据（引用 L1）、已知反例、不能推广到哪里。方法经验、失败与反例、参数和工况边界、工具或数据的特点、偶然发现都算。假设要写验证条件，建议不能冒充实测。
- 导入资料：原文明确的主张和建议写成 L3 并标明"原文主张"，AI 自己的评价另写。
- AI 研究交互：本次得到的可迁移认识，包括失败的教训。
- 与 L4 的关系：L3 是细化的、可以单独检索到的经验；L4 只挑最关键的几条点名并链接过来。

**L4 概览：这是什么，现在到了哪一步，能用来做什么，接下来做什么**
- 包含：对象的用途和问题边界；主要方法或内容；**已经有了哪些关键结论**（点名并链接 L1 / L3 / 结论）；**关键反例与限制**；当前状态；**下一步建议做什么**、还有哪些未决问题。不展开下层，也能知道"它是什么、现在能用来做什么、继续做应该从哪里开始"。
- 导入资料：材料讲什么、能用来做什么、适用边界、主要内容的结构（链接到对应的 L1）；下一步可以是"还有哪些部分未导入或未核实"。
- AI 研究交互：研究问题、目前的结论与证据强度、最重要的反例、下一步建议与阻塞。
- 不包含：细节的复述。每个关键结论、数字、方法都要就近链接到下层。

同一段原文可以同时贡献给多层：例如随笔中的一段经验，原话保留在 L1，提炼出的判断写进 L3 并引用那个 L1 块，其中最关键的一条再由 L4 点名。

**原则 2：保全。** 任何**会消失或不会被检索读到**的有用细节，必须完整落在 L1（L0 原件只登记、不进记忆正文）。

- 导入外部资料：原文就是来源，L1 要保留原文中所有有用的内容。
- AI 交互中的工作：对话和执行过程就是来源，对话结束后就消失，L1 是唯一完整的记录。

**原则 3：先保全，再提炼。** 先写 L1，再写 L2–L4；上层在写到关键事实、数字、方法时，就近用 `[[@记录]]` 或 `[[@记录#块]]` 引用 L1。引用到块就够了，不要求逐句引用。

**原则 4：出处分开。** 原文的内容、本次工作的观察、AI 的推断分开写明。转写原文时，AI 的注解单独成块，标"整理者注"；原文给出的结果可以写成 fact 类结论，依据指向原文出处，但不算已复核。

**原则 5：组织顺序是默认值，独立可读才是要求。**

- 转写原文：默认按原文顺序，开头写一小段上下文（在原文的位置、依赖什么）。
- 本次工作产生的技术单元：默认按"问题 → 方法 → 结果 → 限制 → 复算依据"排列（现有 RECORDING §4）。
- 两种顺序都不强制；不论哪种，都要满足 RECORDING §2 的"只看这一条也能读懂"，依赖的定义块用 `requires_block_ids` 带上。

**原则 6：拿不准时偏向保全**（规则内的第一道兜底）。

- 拿不准有没有用：保留。
- 拿不准放哪一层：放 L1。细节层不会丢，以后可以再从 L1 提炼上层；反过来，压缩掉的细节就找不回来了。
- 拿不准 `unit_type`：用 `general`。
- 只省略能确定没有用的内容（目录、版权页、致谢、重复的页眉页脚、与主题无关的套话），并登记省略了哪里、为什么省略（D-05）。

**示例（默认划分，帮助不走偏；遇到表里没有或混合的形态，按原则 1–6 逐段判断）**。RECORDING 中保留现有的对象类型表（§3），新增以下两张表。

表 A：常见内容片段怎么落层

| 内容片段 | 落在哪里 |
|---|---|
| 定义、符号表、方程、算法步骤、伪代码、接口说明 | L1（`method`），定义单独成块供依赖 |
| 推导过程 | L1（`derivation`），每一步保留，变量与成立条件写全 |
| 实验设置、工况、样本、结果表、误差 | L1（`experiment`；本次执行用 `run_ref`，原文实验用 `origin`）；大数组留在 L0，L1 写明怎样引用 |
| 数据分析、对比、评测 | L1（`analysis`） |
| 图、图注 | 图片放进附件（`sources_attach`），L1 在原位置引用并照录图注 |
| 表格 | 转成 Markdown 表格保留在 L1；太大的留在 L0 并在 L1 写清列含义和引用位置 |
| 代码片段、命令、配置 | L1，原样保留，写明版本与环境 |
| 原文的观点、讨论、随想 | 原话保留在 L1（`general`）；能复用的判断另写 L3 并标"原文主张" |
| 经验、教训、注意事项、反例 | L3，每条带条件与反例；原文出处或本次 L1 作为依据 |
| 版本演进、排错经过、会议讨论与决定 | L2（只写实际发生或原文记载的），细节引用 L1 |
| 摘要、引言、结论段 | 帮助写 L4；原文的结论原话同时保留在 L1 |
| 目录、版权页、致谢、页眉页脚、重复内容 | 省略，在 L0 的 `omitted` 登记 |
| 识别不了的扫描页、公式图片、看不清的图 | 写成缺口，不猜 |

表 B：常用类型的具体划分

| 类型 | L0 | L1 | L2 | L3 | L4 |
|---|---|---|---|---|---|
| 核心算法 / 算法介绍 | 公司定义文档、实现版本 | 按模块：方程、符号、步骤、接口、参数表、伪代码、数值处理 | 文档记载的版本演进或排错 | 适用域、参数选取经验、已知失效情形 | 算法用途、输入输出、适用边界、模块结构 |
| 实验报告 / 实验数据 | 原始数据、实验记录 | 每组条件一个单元：目的、设置、工况、结果表与图、误差 | 实验的实际顺序与调整 | 由结果得出的有条件结论、异常与反例 | 实验目的、关键结果、限制、待补实验 |
| 科研论文 | 论文原件 | 按章节：问题、方法、推导、实验设置与结果、讨论原文 | 一般不写 | 论文主张（标"原文主张"）与本次评价分开 | 问题、贡献、关键结论、局限、与本工作的关系 |
| 公式推导笔记 | 原稿 | 每段推导一个单元，步骤完整 | 推导走过的弯路（如有记载） | 推导成立的条件、常见错误 | 推导目标与结论 |
| 随笔 / 经验帖 / 内部说明 | 原文 | 有实质内容的段落原话保留（`general`） | 文中讲述的经历 | 每条经验、教训一条 | 主题、主要观点、适用场景 |
| 会议纪要 / 讨论记录 | 纪要原件 | 每个议题的事实、数据、方案细节 | 讨论经过与决定理由 | 形成的共识与约束 | 议题、决定、待办与负责人 |
| 幻灯片 | 原件 | 每页的讲解文字与图（附件），按页 | — | 讲者的经验与建议 | 主题与结构 |
| 工具 / 数据说明 | 版本化的工具或数据 | 用法、参数、字段定义、处理流程、示例 | 选型或治理经过 | 使用陷阱、兼容性边界 | 用途、接口、数据范围 |
| AI 研究交互（本次工作） | 本次的 Run、输入数据 | 实际做法、计算、结果，可复算 | 实际的尝试、取舍、失败 | 一切可迁移的认识与教训 | 研究问题、关键结论与证据强度、关键反例、当前状态、下一步建议 |
| 排错 / 调试过程 | 日志、报错、版本 | 复现步骤、根因分析、修复方法 | 排查经过（试过什么、排除了什么） | 症状 → 原因 → 处理的经验 | 问题、根因、修复状态、遗留风险 |

## 3. 兜底：定义总会有失手的时候

| 层 | 机制 | 覆盖 | 状态 |
|---|---|---|---|
| ① 规则内 | 原则 6 的不对称默认：拿不准就保留、放 L1 | 全部 | 新增（规则） |
| ② 程序覆盖报告 | 把原件的抽取分段与 L1 的 `origin` 和正文逐段对比，列出覆盖偏低且没有登记为省略的段落，附原文开头片段（D-06） | 导入外部资料 | 新增 |
| ③ 检索 | 原件分段已经作为 source 投影进入检索：L1 漏掉的细节仍能检到原文段落，读到后就地补写 L1 | 导入外部资料 | 已有 |
| ③' 收口清单 | `memory_consolidate_prepare` 已经列出没被引用的 Run 和 L0；新增"没有被任何 L2–L4 引用的 L1"（D-08） | 全部 | 扩展 |
| ④ 人工 | 用户在工作台看展开稿（D-07），觉得哪里简略就写笔记交给 AI（R15）；AI 按 `origin` 只重做对应段落 | 全部 | 已有，接上 |

如实说明：② 只对导入有效，因为 AI 交互中的工作没有原文可以对比；这类工作的兜底是 RECORDING §2 的回读自查、③' 和 ④。覆盖报告只提示、不阻断：合理的压缩（例如省略目录）也会拉低比例，判断仍由 AI 做并写明理由。

## 4. 决定

| 编号 | 决定 | 理由 |
|---|---|---|
| D-01 | **本质原则写进 RECORDING §1**（§2 的原则 1–6），类型表降为示例。burrowl-work 的"导入已有资料"改为：登记 → 抽取与快照（D-04）→ 按原文分批写 L1（保全）→ 写 L2–L4（提炼，就近引用）→ 处理覆盖报告 → 检索验证。RECORDING §4 写明两种默认顺序 | 按内容片段判断才能覆盖穿插、混合和没见过的形态 |
| D-02 | **L1 契约**：① 新增可选的 `origin = {source_ref, locators[]}`，`source_ref` 是原件的固定引用，`locators` 是原件抽取分段的标签（页、标题路径、幻灯片）；块上可选 `locators[]`，用来细到块。② `unit_type` 增加 `general`（不属于实验、方法、推导、分析的内容，如说明、观点、经验叙述）。③ `experiment` 必须有 `run_ref` **或** `origin`（外部资料中的实验以原文为依据）。旧记录照常读取；保留 v0.7.0 兼容标本测试 | `origin` 是覆盖报告、变更对比、工作台从原文跳到记录的共同基础；`general` 让"拿不准类型"有一个不会写错的位置 |
| D-03 | **docx 抽取**：`index/extract.py` 增加 docx，用 zip + XML 解析（与 pptx 相同，不加依赖），分段按标题路径，表格转为 Markdown 表格，提取内嵌图片 | 公司文档多为 docx |
| D-04 | **原文快照（服务提取）**：导入时（`sources_register` / `register_many` 加参数 `snapshot: true`，或之后单独调用）服务保存抽取结果快照：每段的标签、文本、指纹，以及原件指纹。快照属于数据目录的状态（不可重建：原件一变就无法再生成），放在 `sources/snapshots/<SRC>/<原件sha>.json`，随备份打包；**不保存原件本身** | 用户决定：只复制提取出的资源。比较原件比比较记录更直接，但需要旧版内容；纯文本快照很小 |
| D-05 | **图片与省略登记**：① 新增 `sources_attach`：把抽取缓存里的某张图片（按原件 + 资源标签），或一个已登记的图片文件，复制为数据目录内的受控附件（`attachments/<sha256>.<ext>`，按内容寻址），登记为来源并返回固定引用，供 L1 的 `figures` 使用。② L0 记录 payload 增加可选 `omitted = [{locators, reason}]`，登记有意省略的原文段落 | 图片在记录中有备份，迁移时一起走；省略写明理由，覆盖报告就不会再把它们列为缺口 |
| D-06 | **覆盖报告**：`memory_document(view="coverage", source_id)`（只读）对快照中的每一段计算：被哪些 L1 的 `origin` 认领；L1 对应正文与原文的字符量之比，以及字符 n-gram 重合度；是否在 `omitted` 中。输出"没有被认领"和"认领了但明显偏短"的段落，附原文开头 200 字。导入第 5 步和收口时由 AI 查看，工作台也显示 | 确定性的指标，不调用 AI；只提示不阻断 |
| D-07 | **展开稿是视图，不是记录**：`memory_document(view="expansion", source_id)` 按快照的段落顺序拼出认领它们的 L1 块，省略段显示"已省略：理由"，没有认领的段显示为缺口。工作台在对象页提供"原文展开"标签页 | 由程序按 `origin` 排序，AI 不需要再维护一份文稿，内容永远与 L1 同步 |
| D-08 | **就近引用不设提交警告**：规则写原则 3；`memory_consolidate_prepare` 增加 `unlinked_details`，列出没有被任何 L2–L4 的正文链接或展开引用指向的 L1，AI 逐项补引用或写明不需要的理由 | 给出具体是哪几条，比一个通过 / 不通过的指标更有用 |
| D-09 | **原件变化后的语义维护**：系统已能按指纹发现原件变化；新增按快照逐段对比，得到新增、删除、修改的段落，通过 `origin.locators` 找到受影响的 L1（没被认领的新段落单独列出），生成 R16 维护候选。AI 起草修订稿，用户在工作台执行；执行后保存新快照，旧快照保留 | 只需重写受影响的 L1；对比是确定性的，不需要拿 AI 的记录去比 |
| D-10 | **正文中的长 ID**：提交时检查 L1–L4、文稿章节的正文：在代码块和行内代码之外出现 `MEM-`/`SRC-`/`RUN-`/`RS-` 加 UUID，或 64 位十六进制哈希，就拒绝提交（`UNREADABLE_REF`）。每项给出完整路径和可以直接替换的写法（记录换成 `[[@短名]]`；原件换成对应 L0 记录的 `[[@短名]]`，没有 L0 时提示先登记）。已有记录由 `system_validate` 扫描，程序生成"引用改写"维护计划（只替换引用、自动写修订理由），用户在工作台预览后执行，不调用 AI | 改写方式是确定的，AI 当场改一次就行；修正历史记录不增加 AI 的工作量 |
| D-11 | **工作台引用可点击**：来源、正文链接，以及正文中的 `[[…]]`（按记录的 `links` 解析）都改成链接：记录跳到记录页（带修订号与块锚点），结论跳到复核页，原件跳到原始材料。列表显示标题或短名，完整 ID 放在悬停提示里 | 用户要求 |
| D-12 | **后台运行**：新增 `burrowl start / stop / restart / status / open`。`start` 以无窗口的后台进程运行，把进程号、端口、网址、版本写进 `.burrowl/server.json`，日志写到 `.burrowl/logs/serve.log`；`open` 在服务已运行时直接打开网址，没运行就先启动。端口和 token 在第一次启动时选定（端口选未被占用的）并保存，以后网址不变；端口被其他程序占用时换一个并告知。`status` 和 `start` 发现进程已不存在时清理残留记录。`serve` 保留为前台模式。**不做开机自启** | 不占命令行窗口；网址固定，可以加书签 |
| D-13 | **任务管理器里能认出来**：打包时把自带 Python 的 `pythonw.exe` 复制一份并改名为 `burrowl-workbench.exe`，后台服务用它启动，任务管理器显示这个名字，可以直接结束（记录写入是原子的，最多丢掉正在进行的那次请求）。开发环境（`uv run`）没有这个文件，就用 venv 的 pythonw | 用户要求可以手动结束 |
| D-14 | **首页停止 / 重启**：首页显示"运行中的版本 / 已安装的版本"，不一致时提示重启。"重启服务""停止服务"是用户操作（`effect="user"`，AI 调用不到）。重启：服务用已安装的 `current` 启动器拉起新的后台进程，等它接管端口后自己退出；页面轮询，恢复后自动刷新。说明里写明：AI 客户端通过 stdio 运行的 MCP 是另外的进程，需要重启客户端 | 支持版本更新后在页面上完成重启 |

### 补充决定（2026-10-14，用户确认；优先于 §2 和 D-01 / D-06 的旧表述）

| 决定 | 现行约定 |
|---|---|
| D-16 | 授权范围内默认完整转录，不由 AI 先筛“有用部分”。按原文逻辑段落组织；同一逻辑段落中意思或用途差别较大的部分继续拆分。原文章节、标题、编号和论证关系是依据；页码、快照 key、固定长度只是定位或读取边界。L1 开头的整理者注说明原文组织逻辑、位置、切分依据与必要上下文；不因拆分丢掉条件、推导步骤、图注或例子。省略仅限不承载实质信息的部分或用户明确排除的范围，并在 L0 登记位置、范围、理由 |
| D-17 | 覆盖仍是派生提示，不阻断正常保存，也不判定“完整导入”。文字采用保守的九成阈值，字数比或重合度任一不足都提示，短段不豁免；另现算图片附件、原位置正文引用和展示可用性，附抽取警告。全部原文已读、逐段逐图比对、省略有理由且缺口处理后，AI 才能宣称完整导入；标签和指标都不能代替内容核验 |
| D-18 | 导入抽取不沿用检索的 40 张图片限制；OCR / 预览缩略图与原始资产分开，PNG/JPEG/WebP 附件保留原始字节、尺寸和透明度，原件变化后拒绝用旧登记提取。补上 DOCX 表格内图片；无法抽取的 PDF 矢量图、DOCX 非正文部分、Markdown 图片等明确警告，并按原件补齐或报告缺口。旧快照和旧附件保持可读，不自动替换历史图 |

## 5. 不做的

- 不按文档类型强制套模板，不让 AI 先给整篇文档判类型。
- 不保存原件副本，只保存纯文本快照和提取出的图片。
- 不在提交时检查"L4 是否引用了下层"。
- 覆盖报告不调用 AI 判断，也不阻断提交。
- 不做开机自启，不写注册表里的软件或卸载条目（现有的 `BURROWL_ROOT` 与 Path 用户环境变量保持原样，`-NoPath` 可以不写）。
