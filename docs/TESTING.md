# 按影响选择验证

本页规定**测试强度**，不规定固定的开发流程。根据功能重要性、改动大小、影响范围和失败后果选择有用的检查，并把选择理由写进本次计划或摘要。

## 测试分层

| 层 | 位置 | 内容 | 命令 |
|---|---|---|---|
| 单元 | `tests/unit/` | core：校验、哈希、原子写与锁、路径安全；查询计划、重排条件；备份包 | `uv run pytest tests/unit` |
| 服务 | `tests/service/` | 在临时数据目录（浮点样例的副本）上测各服务的行为与失败边界；使用确定性的假向量 | `uv run pytest tests/service` |
| 接口 | `tests/interfaces/` | HTTP 安全与路由、MCP（进程内与 stdio 真实拉起）、操作经组合根的完整链路 | `uv run pytest tests/interfaces` |
| 连接器 | `tests/connectors/` | WeKnora 适配器（模拟 v0.8 REST）与同步引擎的端到端；LightRAG 连接器（假实现的合约测试，装了 lightrag-hku 时再跑真实 1.5.7） | `uv run pytest tests/connectors` |
| 前端组件 | `frontend/src/**/*.test.tsx` | 页面行为与发给后端的参数（模拟 fetch） | `npm --prefix frontend test` |
| 浏览器端到端 | `frontend/e2e/` | 真实后端 + 构建产物 + 系统 Edge：阅读会话双向交互、复核后过滤、中枢发布、维护与原始材料、工作台笔记从交给 AI 到执行方案、维护计划从勾选候选到执行、删除与恢复记录和对象 | `npm --prefix frontend run e2e` |
| 打包 | `packaging/build.py` 与一次真实离线安装 | 中文和空格路径、版本切换、MCP 登记与拉起 | 见下文"不能省略的检查" |

带标记的测试默认跳过：

- `real_model`：需要本机模型。
- `live_hub`：需要 `WEKNORA_URL` 和 `WEKNORA_API_KEY`。

## 选择范围

| 改动 | 验证目标 | 通常采用 |
|---|---|---|
| 纯文档、规则调整 | 含义、链接、入口正确 | 定向核对；`burrowl skills check` |
| 局部低风险功能或明确缺陷 | 改后可用、关键失败边界不回退 | 受影响模块的测试；必要时补真实故障用例 |
| 重要功能、跨模块、状态或契约变化 | 主要链路、调用方、失败与兼容边界 | 相关各层测试；前端类型检查与相关组件测试 |
| 全局重构、发布 | 整体可交付 | 全部测试 + 浏览器端到端 + 打包与离线安装 |
| AI 调用方式、Skill、记录写法变化 | AI 实际能完成任务 | 软件检查之外，用真实 AI 跑对应场景（burrowl-work / burrowl-read / burrowl-consolidate），结果单独报告 |

通过必要检查后，只有新改动、失败或未解决的风险才扩大或重复验证。

## 测试点怎样来

- 从本次目标和架构影响路径出发，识别用户可观察的行为、状态转换、关键的拒绝与失败、兼容边界，再选择已有测试；有缺口时补行为用例。
- 真实故障要尽量固化原触发条件，修复后验证正确行为。
- 不只匹配实现文本，不为增加数量而重复测试。
- 已有测试不能为了通过而放宽断言。预期行为变了，在测试里写明理由。

## 不能省略的风险检查

**规范存储与并发**

- 提交的 CAS、幂等、暂存回读、锁清理（包括并发清理不能移走新锁）。
- 已校验记录缓存：命中与重读等价且返回独立副本、其他进程的新提交可见、完整性检查绕过缓存、容量有界；提交与 inspect 不重读未变化对象的记录（`tests/service/test_record_cache.py`）。
- Run 作为执行证据（R14）：扫描不读 Run 卡、按编号与位置定位、受限独立 Run 的材料仍受限、拒绝向 Run 提交与把 Run 放进检索范围、关系图 Run 节点来自引用、丢弃与恢复；全局关键操作记录与 `runs.search` 的惰性读取结果与全量读取一致（含"最早结束、最后改名"），且不读全部 Run 卡（`tests/service/test_run_evidence.py`）。
- 删除与恢复（R22）：墓碑提交后当前快照与检索中没有、按修订号仍可读、恢复逐字节相同；被引用与指针记录的护栏、一起删除与一起恢复；不能新引用或改写已删除的记录；对象回收站的护栏（外部引用、嵌套对象、概念库、HEAD）、被采用文档的原件保留、投影删除与重建、关键操作记录（`tests/service/test_deletion.py`）。
- 操作内对象列表复用：保存中的普通读取只扫描一次；写业务卡后作废；发布前复核与读取回源仍重新扫描，操作开始后业务卡被改照样报 STALE_BASIS（`tests/service/test_owner_scan_scope.py`）。
- 维护计划交给 AI（R16）：候选成计划只含所选记录、候选标为 planned；未写处置不能执行；退回保留处置并记下意见；执行后修订署名为 AI、原因带计划编号；`maintenance_apply` 不在 MCP 工具中。
- 工作台笔记（R15）：每个状态只由一方推进（AI 只能回写 queued）；方案的步骤类型、步数、同对象多次提交与过期 HEAD 被拒绝，预演不写入；执行时 HEAD 变化不写入并退回，中途失败如实列出已写入步骤；编号在清除后不复用、旧列表格式可读。用户专属的笔记操作不出现在 MCP 工具中。
- 读取路径对受限来源的过滤；来源停用或设为 restricted 后，读取被拒的记录也从检索结果和关系图中消失，恢复后重新出现（E9，`tests/interfaces/test_source_access_ops.py`）。

**来源与授权**

- 来源登记不可改写（只能提高敏感级别），停用只能由用户操作。
- 受限对象的材料不能进入 Run 或来源登记。
- 工作根：工作目录内的来源自动归根；整体搬家必须指纹一致；备份带外部原件，恢复按映射/原位/默认目录重定向，冲突时不写任何文件（`tests/service/test_work_roots.py`）。
- 来源内容变化后，引用它的结论显示依据失效。

**归属判定与关键操作记录（R13）**

- 归属候选与阅读会话第一轮的对象次序、筛选包一致；判定不读任何对象的全部记录（`tests/service/test_routing.py`）。
- 判定之后同一问题的 `reading.start` 复用判定的召回（第一批与重新计算完全相同，含 digest 与缺口）；问题、范围、过滤、配置、任一对象的提交或索引水位变化、超时都重新召回；未就绪的对象不妨碍复用，只多一条缺口（`tests/service/test_screen_reuse.py`，R18）。
- 新建或采用的对象立即建检索投影、判定能找到；新建后开阅读重新召回，沿用路径复用；所属对象尚无记录时不进入该会话的召回，有记录后照常参与（`tests/interfaces/test_owner_create_index.py`）。
- 查询计划的保护项与数值校验在报错与 details 中写明缺少或多出的项及对应改写（`tests/unit/test_query_plan.py`）。
- `attribution` 存进回执、参与幂等、结构校验；关键操作记录只列改变资产的操作、分页不重不漏、受限记录不外泄、读取操作不产生条目（`tests/service/test_activity.py`）。

**记录契约与链接**

- 契约只做增量：浮点样例全部记录的 content_hash、record_hash、结论指纹不变（`tests/service/test_links.py`）。

**AI 填写的字段与报错（R20）**

- 契约标注与服务行为一致：每类记录逐字段省略，标 required 的失败且路径指向该字段，标 optional 的通过；服务端字段写了被拒。草案 `owner_id`、`sensitivity` 可省略，修订沿用原值；错误一次列全、路径从参数根算起、带字段说明与 `memory_contract` 提示；总结保存与关联的路径换成各自参数（`tests/service/test_ai_fields.py`）。
- Skill 提到的工具每个参数都有说明、结构化参数声明了字段、说明里用 MCP 工具名、形状与示例通过校验；顶层与嵌套参数的错误一次列全；MCP 不预校验（类型错误也返回统一结构）、JSON 字符串参数照常解析；意外异常只返回 `incident_id`，堆栈在日志里；被拒绝调用的统计不含参数内容；时间字段带时区写法经 MCP 保存为 UTC、只写日期时顶层 message 指出字段与写法；请求日志默认不写、full 记下原样参数与 JSON 字符串解析、报错带 request_id、summary 不含内容、环境变量优先于配置（`tests/interfaces/test_tool_errors.py`）。
- 导入不丢细节（R21，`tests/service/test_faithful_import.py`）：docx 按标题路径分段、表格转 Markdown、列表与内嵌图片保留；快照分段按内容对比（改版后未改的段落仍对得上）；附件进数据目录、重复附加幂等；原文中的实验用 `origin` 代替 `run_ref`、`general` 无需其他依据；覆盖报告区分已转写、未覆盖、已省略，展开视图按原文顺序；`unlinked_details` 随上层链接变化；正文新写的长编号被拒并给出替换写法、代码里的不拦；原件改版后维护计划的 `origin_changes` 只把改了的分段标给对应 L1；旧记录的"引用改写"计划执行后正文变为短名链接并解析为 links。前端 `linkify` 只替换已解析的链接、不碰代码（`frontend/src/ui.test.tsx`）。
- 工作台后台运行（R21，`tests/unit/test_server_state.py`）：端口与 token 复用、端口被占时换端口不换 token；进程已退出或 PID 被复用时清除运行信息；旧进程退出时不清掉重启后新进程写入的记录。后台启动、重启、停止的真实进程行为靠手工验收（见设计稿 R21 §8）。
- 真源兼容：每次全量测试都用当前代码读取 `tests/fixtures/compat/` 下所有历史标本，检查四项：
  1. 沿提交链逐条校验全部修订的身份与指纹；
  2. Run（含回收站）、来源登记、阅读会话、工作台笔记、配置都能加载，工作根能重定向；
  3. 问题清单不多于生成时的记录，检索索引与关系图投影能从零重建；
  4. 旧数据上能继续修订和建 Run。

  测试见 `tests/service/test_compat_fixtures.py`。旧标本读不了时，补对旧格式的读取，不改标本、不放宽断言。

**兼容性标本：什么时候生成新的**

已有标本的读取测试每次都跑，只需几秒；新标本只在以下情况生成并提交（`uv run python tools/make_compat_fixture.py`，按当前版本号命名，生成后不再修改）：

- `test_format_change_requires_new_fixture` 失败。它比较当前代码的真源格式指纹与最新标本的记录，指纹覆盖记录契约全文、内容与服务端字段表、提交清单字段、规范哈希算法、备份包格式。
- 改了指纹覆盖不到的落盘格式：业务卡、Run 卡及其回执、来源登记、阅读会话、工作台笔记、配置的字段或版本号。
- 发布次版本或主版本（0.x.0、x.0.0）。

同一版本号只保留一份标本，所以格式变化要先升版本号再生成。标本以浮点样例为底，相同文件在 git 中只存一份，每份新增约 0.5 MB。
- handle 唯一、不可修改；链接的每种写法能解析，歧义和找不到时报错带候选，未解析的概念不阻塞；修订时未改动的链接保持原固定版本，repin 才更新。
- 概念库内有效概念的名称与别名唯一；合并后新链接转向保留页。

**复核**

- 内容变化后复核失效。
- accepted 必须有范围与证据。
- 正式用途只输出范围内已确认的结论。
- 复核过滤在检索中生效。
- 成熟度：执行者为 ai 时不能登记 established（PERMISSION_DENIED）；replicated 需要两份独立依据；established 需要证据类型；升级提议出现在队列中，由人确认后消失。

**阅读会话**（程序替 AI 守的规则，每条都要有测试）

- digest 与理由必填；未判断不能读。
- 读完全部页才能写笔记；quick 只能引用采纳的窗口。
- 对象更新后笔记与综合稿失效。
- 全文补偿的前提与一次性批准；request_id 重试不重复执行；重排 required 时缺模型报错。
- 扩大检索须用户批准、批准只能用一次、别的请求的批准不能借用；联想不接受文本（`tests/service/test_graph_expansion.py`，R19）。
- 图扩展：种子只来自笔记出处、锚点优先；只走跨对象的边，对象内部与已在会话中的对象不出现；失效结论声明的边不扩展；被很多对象引用的来源不中转；焦点改变排序；没有种子时不消耗轮数；扩展来的对象默认定点阅读、升级整读计入上限；关系线索不可作为出处（同上）。
- 可见范围默认值、修订沿用、对象策略优先；非推荐关系名只给 warning、收口时列出（`tests/service/test_discovery_defaults.py`、`tests/unit/test_relation_vocabulary.py`）。结论、已采纳关联、概念页进入发现投影（`tests/unit/test_relation_projection.py`）。
- 可见范围补齐：只列知识类、owner_only、对象未显式保密的记录；计划只能由用户生成、只含候选；执行后全库可见且能被检索到（`tests/interfaces/test_visibility_backfill.py`）。
- 图扩展中结论、块种子带上所在记录：只走入边与对称的关联边，不走记录自己的出边（`test_claim_seed_brings_incoming_references_to_its_record`）。

**MCP 交付**

- effect=user 的操作不暴露给 agent。
- Skill 引用的工具都存在且在默认工具组（`burrowl skills check`）。
- 记录契约示例能通过真实校验（`test_draft_examples.py`）。
- stdio 真实拉起。

**HTTP 安全**

- 只监听 127.0.0.1，需要 token，校验 Host/Origin，设置 CSP。

**前端**

- 类型检查、相关组件测试、构建；涉及交互流程的改动跑浏览器端到端。
- 关系图：结论节点默认显示、来源默认关闭，“提及”类别默认关闭；L1 记录分类与内部块展开分别控制；点击合并连线逐条列关系，按声明修订读取关联说明、结论范围、结构与依据（含 note）；已保存视图中改名前的类别退回默认。浏览器测试必须覆盖真实画布的点击事件与详情读取，不只测试详情组件。

**依赖、模型、打包、启动器**

- 构建安装包，在含中文和空格的路径做一次离线安装；验证同版本重装能更新后端与前端，旧进程不被安装器擅自终止。
- 本地 `--install` 默认重建前端且不生成 zip；发布包和本地安装均携带可读的 `BUILD_INFO.json`。参数与打包分支见 `tests/unit/test_packaging_build.py`；安装脚本用临时根目录回归，不能修改真实数据库或用户级环境。
- 使用真实 Windows 文件占用验证同版本更新：内容相同但时间不同的 DLL 不覆盖；相同大小但内容变化的 DLL 仍报错并保留原内容。同步时还应清理新包已删除的普通文件，保留旧版本目录。
- 验证 `burrowl` 可用、`burrowl mcp-config` 输出的配置能被 MCP 客户端拉起；版本切换与回滚后 `burrowl upgrade` 刷新 Skill。

**检索、表示或语义变化**

- 覆盖索引结构升级清空后只补图的状态：总体仍为 pending，缺失检索通道有明确信息；补偿后不同主题能召回各自记录。检索页显示非空缺口、按原查询补齐并重试；旧请求不得覆盖新查询或阅读包。
- 范围与排除、固定引用、正式准入、预算、复核过滤。
- 涉及效果的改动，要比较准确度、召回、错误关联、延迟和上下文成本，方案见 [R12 设计稿 §7](design/R12_KNOWLEDGE_GRAPH_RETRIEVAL.md#7-评估方案)。改动前后各跑一次、只改一个变量：

  ```
  uv run python tools/eval_retrieval.py --data-dir tests/fixtures/workspace --set tests/fixtures/eval/floating-point.jsonl --scratch --label <名称>
  ```

  样例题集只有 13 题，只看相对变化；真实数据目录的题集放在 `<数据目录>/eval/`（去掉 `--scratch`）。`--channels dense` 单看向量通道。
- 改了嵌入模型或分窗：必须用真实模型（`real_model`）验证窗口不超过模型的真实输入上限。假向量测试发现不了截断问题（E6）。换模型或切窗规则后，旧向量水位必须显示为 stale 并在 reconcile 时重建。
- 后切分（R17，`tests/unit/test_late_chunking.py`）：段落切分覆盖全文且不超过 span；一次编码逐段池化，超出上下文时分批且每批带前缀，**区间外的前后文也进入编码**；L1 记录只编码一次、块向量取自记录、只输出变化的条目；新数据目录写入默认模型而旧目录不变。真实模型（`real_model`）验证整段时与原生向量一致、同一段落在不同上下文中向量不同。改切分参数或模型时，用 R17 §5 的评测方法比较，而不只看单元测试。
- 图投影与图路线（`tests/service/test_graph.py`）：
  - 关闭时检索结果与没有图路线时完全一致；
  - 只返回当前投影、通过同样过滤（层级、类型、复核、敏感级别、owner_only）的条目；
  - rejected / withdrawn 关联和失效结论的要素边不参与扩展；结论声明的边，关系窗口带出陈述与适用范围；
  - 预算上限生效并报告缺口；
  - 打开图路线前后，按题型比较评估结果（尤其是 multihop 与 fact 类的副作用）。

## 结果怎样记录
